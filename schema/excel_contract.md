# Bridgework Excel Contract — v1.0.0

This document is the human-readable version of the Excel workbook contract
enforced programmatically by `src/bridgework/ingestion.py`. Any workbook
that does not conform is rejected with an itemized `BridgeworkSchemaError`
— there is no partial recovery and no silent fallback.

## Ingestion scope (Decision 3, Blueprint §F)

Bridgework ingests Excel **only** as a constrained round-trip: the workbook
must have been generated by `ingestion.write_excel(...)`, and the only cells
a user may legitimately change before re-ingesting are the seven driver
values in `Drivers!B4:B10`. Every other cell is diffed against the original
template on load; any other change is rejected. Arbitrary third-party
workbooks are explicitly out of scope for Phase 1 (Blueprint §N).

## Required sheets (exact names, case-sensitive)

`Drivers`, `Calc`, `Meta`

## Required cells

| Cell | Content |
|---|---|
| `Meta!B1` | `schema_version`, semver string, e.g. `"1.0.0"` |
| `Drivers!B4:B10` | The 7 canonical driver values, fixed row order: `revenue_prior, revenue_growth, cogs_pct, opex_pct, tax_rate, nwc_pct, capex_pct` |
| `Calc!B4:B13` | The 10 line-item formulas (see calculation graph in `canonical_schema.yaml`) |

## Supported formula whitelist

`+  −  *  /  MAX  MIN  IF  SUM  ABS  ROUND`

## Explicitly unsupported (fail-fast)

- VBA / macros
- `INDIRECT`, `OFFSET`
- External workbook links
- Excel Tables / structured references
- Array (CSE) formulas
- Volatile functions: `NOW`, `TODAY`, `RAND`, `RANDBETWEEN`, `CELL`, `INFO`
- Iterative / circular calculation mode

## Reference patterns

Sheet-qualified absolute references only (`Drivers!$B$4` style). No
`INDIRECT`-constructed dynamic references.

## Schema versioning

`Meta!schema_version` must be valid semver. Ingestion requires a **major**
version match with the engine's expected schema version; a minor/patch
mismatch is tolerated with a warning, not a failure.

## Validation behaviour

`ingestion.py` runs every rule above and accumulates **all** violations
before raising `BridgeworkSchemaError` — the user gets one complete report,
never an iterative fix-one-error-at-a-time loop.
